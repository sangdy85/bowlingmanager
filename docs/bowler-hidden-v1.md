# Bowler Hidden V1

## 기능 범위와 활성화

`Team.bowlerHiddenEnabled`의 기본값은 `false`다. 기존 팀과 신규 팀 모두 일반 동호회 UX를 유지한다. 활성화는 웹 시스템 관리 화면에서 DB의 현재 역할이 `SUPER_ADMIN`인 계정만 수행할 수 있다. 모바일 팀장·매니저 API에는 이 값을 변경하는 기능이 없다.

활성 팀에서만 일정 작성 화면에 개인전, 팀전, 이벤트전 설정이 표시된다. 서버도 모든 조회·변경 요청에서 팀 플래그를 다시 확인한다. `INDIVIDUAL`은 이 문서의 개인전 규칙을, `TEAM`은 `bowler-hidden-team-competition-v1.md`의 팀전 규칙을, `EVENT`는 `bowler-hidden-event-competition-v1.md`의 비밀 투표·점수 배분·순차 개표 규칙을 사용한다.

## 개인전 전체 순위와 포인트

- 참가자: 해당 일정에 `ATTENDING`으로 응답한 현재 팀원
- 경기: 팀, 일정의 KST 날짜, 일정 `gameType`이 일치하는 유효 점수(0~300)
- 순위: 참가자별 게임 총점 내림차순
- 동점: Phase 12와 같이 참석자 안정 순서로 연속 순위 부여
- 포인트: 관리자가 일정에 저장한 `rankPoints` 사용, 미정의 순위는 0점
- 점수 수정·삭제: 조회 시 원본 `Score`에서 다시 계산하므로 자동 반영

게임 수가 다른 참가자도 기존 팀 활동 결과와 동일하게 총점으로 비교한다. 공정성을 위해 동일 게임 수를 강제해야 한다면 별도의 제품 규칙이 필요하다.

## 최근 게임 모집단

그룹 준비 자료의 최근 50/12는 세션 평균이 아닌 개별 게임 점수다. 안정적으로 사용자 ID가 연결된 다음 원본만 사용한다.

- `Score` 개인/팀 기록
- `LeagueMatchupIndividualScore` 상주리그의 게임별 원점수
- `TournamentScore` 대회 게임별 원점수

핸디캡을 더하지 않은 0~300 점수만 사용한다. 날짜 내 정렬은 게임 순서와 안정 ID를 사용한다. 50개 또는 12개 미만이면 보유 게임 전체, 0게임이면 `null`과 `UNRATED`를 반환한다. 이름 유사 검색으로 다른 사람의 기록을 연결하지 않는다.

## 기대점수와 그룹점수 결정 대기

요구사항에 공식이 정해져 있지 않으므로 V1에서 값을 임의 생성하지 않는다. API는 `expectedScore`, `groupingScore`, `baseTier`, `finalGroup`을 `null`로 반환하고 `groupingPolicy=PENDING_PRODUCT_DECISION`을 명시한다.

검토 후보:

1. **최근 가중형:** 최근 50 평균 40% + 최근 12 평균 60%. 최근 폼에 민감하고 설명이 쉽다.
2. **표본 보정형:** 전체 평균을 기준으로 표본 수에 따라 최근 12의 가중치를 0~60%로 증가. 신규 회원의 작은 표본 과대평가를 줄인다.
3. **추세 제한형:** 최근 50 평균에 `(최근12-최근50)`의 50%를 반영하되 ±10점으로 제한. 급격한 변동을 억제한다.

공식 확정 시 `formulaVersion`을 설정에 저장하는 방식을 권장한다. 그룹점수도 공식이 확정될 때 같은 버전으로 관리해야 한다.

## 티어와 병합 정책

정책 확정 이후 적용할 표준 경계는 `A >= 200`, `190 <= B < 200`, `180 <= C < 190`, `170 <= D < 180`, `E < 170`이다. 현재 pure helper와 테스트만 제공하며 자동 배정에는 사용하지 않는다.

병합 helper는 인원이 2명 이하인 티어를 바로 인접한 다음 티어와만 합친다. 한 그룹은 최대 두 원본 티어를 보존하고 화면 이름은 A조부터 다시 매긴다. 세 티어 병합은 하지 않으며 3명 미만이면 `minimumRecommendedMet=false`로 남긴다.

## 개인정보와 레인 관계

팀장·매니저만 모든 참가자의 최근 50/12 자료를 볼 수 있다. 일반 회원은 전체 경기 결과와 자신의 최근 자료만 본다. 이메일, 사용자 ID, 토큰은 반환하지 않는다.

Skill group과 lane assignment의 결합 정책은 확정되지 않았다. 기존 레인 추첨은 그대로 유지하며 두 기능을 임의로 결합하지 않는다.
