## 데이터 구조
KingPerfectEdition(월별 회차/규칙/상태/버전), Entry(센터 회원/자격/핸디), Attempt(모든 예선 시도), Seed(24명 확정 스냅샷), Match(단계/테이블/레인), Seat(참가자/핸디/확정 점수/순위), Game(null 가능한 게임 점수), Fee(개별 발생/납부), Audit(사유/담당자/전후 스냅샷/요청 키), SideEntry, LuckyWin의 11개 전용 모델.
- 회원/대회/경기/점수의 관계는 외래키와 Restrict로 과거 결과 삭제를 방지한다.
- 회차+월, 회차+회원, 회차+시드 위치, 회차+단계+매치, 경기+참가자/위치, 자리+게임, 참가자+과금 원천, 회차+요청 키, 당첨자에 유니크 제약.
- 스냅샷의 attemptId/editionId 일부는 참조 식별자다. 서비스에서 동일 회차를 검증한다. 원시 SQL 외부 쓰기에 대한 복합 회차 무결성까지 DB 제약으로 강제하지는 않는다.
- 변경은 회차 revision 조건부 증가, 데이터 변경, 전후 감사 로그를 하나의 트랜잭션으로 처리한다. 실패 시 전체 롤백.
- 같은 요청 키/같은 내용/같은 담당자 재시도는 재실행하지 않는다. 같은 키의 다른 요청은 차단.
- 재확정 시 삭제하는 후속 대진·결과는 이전 감사 스냅샷에 보존한다. 참가비 원장은 삭제하지 않는다.
- 사용량이 큰 회차에서는 전체 스냅샷 감사 방식의 저장 용량/성능을 운영 전 측정해야 한다.

## 출력과 접근
- 관리자 전용 Server Actions는 세션의 사용자 ID로 서비스 권한을 재검사한다.
- 다른 센터 URL로 대회를 조회하는 경우 notFound.
- 비관리자에게는 공개 완료된 회차의 결승 순위/이름/원점수와 행운권만 전달한다. 원장/승인 정보/관리자 이력은 제외.
- 기존 일반 대회 설정 액션으로 KING_PERFECT 상태·규칙을 변경하지 못하도록 차단.
- XLSX: 예선 순위, 대진/전체 점수, 참가비, 행운권, 확정 시상 시트.
- 인쇄: 현재 표시한 대진/결과 탭의 print CSS, 브라우저 PDF 저장.
- 반응형: 작은 화면 단일 열 대진, 가로 스크롤 표와 탭, 큰 터치 버튼.
- 기본 대회명 수정, 참가자 셀프 접수, 별도 Flutter 전용 화면, 이미지 파일 직접 다운로드, 드래그 배치는 이번 구현 범위에 포함하지 않았다.
