4. 적용 범위와 실제 흐름
상주리그: 기존 주차 선택기 하나를 재사용한다. 서버에서 roundId와 roundNumber(week)를 비교한다.
선택 주차까지의 누적 팀 순위/시상, 팀별 개인 순위, 해당 주차 매치 기록, 설정된 개인 평균 TOP 인원과 기존 결과 링크를 만든다.
미완료 경기 또는 경기 없는 주차는 서버에서 거부한다. 선택 변경은 열린 미리보기를 닫고 이전 응답을 무효화한다.
CHAMP/EVENT: 참가자·레인배정·최종 결과 유형을 지원한다.
최종 결과는 실제 참가자(대기자 제외) 전원의 설정된 게임 점수가 존재해야 한다.
현재 LeagueRound 모델에는 별도의 결과 확정 플래그가 없어 저장된 점수의 완전성을 확인한다. 신규 확정 상태나 migration은 만들지 않았다.

관리자 클릭 → 서버 권한/대상 검증 및 최신 데이터 조회 → 공지 생성 → 관리자 확인/수정 → 공유 범위 확인 → 공식 공유 화면 → 관리자가 BAND에서 대상 밴드와 최종 게시를 선택한다.
문구를 수정하면 확인 체크를 해제한다. 기록 변경 시 '최신 공지 다시 불러오기'로 다시 조회한다.
클라이언트의 점수/본문/revision은 서버 공지 생성의 입력으로 사용하지 않는다.
생성된 공지에는 연락처·토큰·비공개 첨부파일을 포함하지 않는다. 기존 결과 URL의 접근 권한을 변경하지 않는다.
외부 게시 전 관리자가 선수 이름/팀/기록의 공유 범위를 확인해야 한다.

공식 공유 서버 Action과 생성 경로는 OAuth 연결/토큰/BandPost 모델이나 외부 BAND API를 사용하지 않는다.

OAuth 코드, 토큰 암호화, 연결 모델, API 자동 게시, 게시 이력과 기존 엔드포인트를 삭제하지 않았다.
공식 공유 화면을 열어도 게시 성공·알림 발송을 기록하지 않는다. BAND 게시 완료 여부는 공식 공유 API로 확인할 수 없다고 안내한다.

6. PC/모바일/제약
공식 문서: https://developers.band.us/develop/guide/share
PC: https://band.us/plugin/share?body=...&route=bowlingmanager.co.kr
모바일: bandapp://create/post?text=...&route=bowlingmanager.co.kr
직접 클릭에서만 PC 팝업/모바일 앱 링크를 실행한다. route는 고정 허용 도메인이다.
팝업 차단 시 새 탭 링크와 복사를 제공한다. 모바일은 앱 호출과 별도 웹 공유 대안을 함께 제공한다.
URL 안전 기준은 자체 보수적 기준 8,000자이며 BAND 공식 제한값으로 주장하지 않는다.
이를 넘으면 본문을 자르지 않고 전체 복사 후 빈 공식 공유 화면에 붙여넣도록 안내한다.
PNG 자동 첨부는 지원하지 않는다. 기존 4종 개별/전체 다운로드 후 BAND에서 수동 첨부한다.
실제 BAND 로그인/최종 게시/푸시, 실기기 BAND 앱 실행 및 긴 글 빈 공유 화면의 BAND 측 동작은 미검증이다.
추가 확인: QA에서 실제 창 열기를 명시적으로 허용한 후 새 탭 공유 링크로 공식 BAND 로그인 화면(auth.band.us/login_page) 도달을 확인했다. 로그인은 진행하지 않았다.

11. 추가 요청: 사진을 함께 올리는 준비 기능
미리보기 안의 '사진으로 함께 올리기'에서 준비/미리보기/개별 PNG 저장을 제공한다.
상주리그는 기존 공식 결과표 4종(팀 순위·시상, 팀별 개인 순위, 매치 기록, 개인 평균 TOP)을 그대로 캡처한다.
CHAMP/EVENT의 해당 공지는 서버에서 검증한 전체 내용을 이미지로 만든다. 짧은 공유 안내와 분리하며, 긴 기록은 여러 장으로 나누고 내용을 자르지 않는다.
사진 준비 시 관리 권한/회차/완료 상태와 최신 공지를 다시 확인한다. DB 공지가 변경되었으면 최신 내용으로 바꾸고 확인을 다시 받는다.
주차/회차/공지 문구/새 미리보기 변경 또는 창 닫기 시 준비 사진과 File 객체를 비운다. 늦은 응답은 기존 요청 번호 검사로 무시한다.
파일 공유 지원 기기에서는 준비한 File과 수정 문구를 클릭 즉시 navigator.share에 전달한다.
지원 여부는 navigator.canShare({files, text})로 검사하며, 파일 생성 후 별도 버튼 클릭으로 공유해 사용자 활성화를 유지한다.
기기 공유창의 BAND 표시 여부와 실제 사진/문구 수신은 기기·앱에 따라 달라지므로 보장하지 않는다.
미지원/공유 취소/오류 시 사진 저장과 문구 복사 후 BAND에 직접 첨부할 수 있다.
공식 BAND URL에는 문구만 전달하며 지원되지 않는 사진 업로드 파라미터/API를 추가하지 않는다.
사진 공유 완료 Promise도 게시 성공으로 기록하지 않는다.

추가 브라우저 QA 결과 (가상 데이터, 네이티브 공유는 전달 데이터 캡처로 대체):
- 1주차 공식 PNG 4종 생성, 미리보기와 개별 저장 캡처 확인.
- 문구+사진 전달 데이터에 같은 1주차 본문과 PNG 4개의 이름/타입/실제 바이너리 크기가 함께 포함됨.
- 파일 공유 미지원 시 비활성화와 수동 첨부 안내 확인.
- 공지 문구 수정 시 사진/확인 체크가 무효화됨.
- CHAMP 참가자 공지 PNG 생성 및 공유 취소 안내 확인.
- EVENT 최종 순위 공지 PNG 생성 확인: 1200x1094, 123275 bytes, PNG signature 일치.
- 실제 BAND 앱으로 파일을 전달하거나 게시하지 않았으며, 실기기 BAND 수신 확인은 배포 전 수동 점검 항목이다.
QA 기본값은 공유를 캡처하며 실제 기기 공유창은 열지 않는다. '실제 BAND 공유 창 열기'를 직접 켠 경우에만 원래 브라우저의 BAND 창/파일 공유 지원 여부와 기기 공유창을 사용한다.
운영용 컴포넌트에는 이 가상 공유 캡처를 넣지 않았다.

https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare

12. 추가 요청: 간단한 안내 및 사진 위/아래 기본 문구
공식 공유의 기본 안내는 대회명, 선택 주차(회차), 항목명만 표시한다.
예: '대회명\n1주차 · 공식 결과표 4종'. 자동으로 긴 점수/순위/결과 링크나 서비스 꼬리 문구를 추가하지 않는다.
원래 전체 공지 생성 결과는 별도로 유지하여 참가자/레인/최종 결과 PNG에는 전체 기록이 들어간다. 기존 API 자동 게시 본문은 그대로 유지한다.

설정 경로:
- 상주리그: 대회 관리 → BAND 게시글 설정
- 챔프전/이벤트전: 해당 회차 → 설정 → BAND 게시글 설정 (대회 공통)
사진 위/아래 기본 문구는 각각 2000자까지 지정할 수 있고 비워두면 추가하지 않는다.
기존 Tournament.settings JSON의 bandOfficialShare에만 저장하며 schema/migration은 추가하지 않는다.
기존 gameCount/회차별 정원/BAND 자동 게시 설정 등은 보존한다. 저장 시 기존 설정 문자열을 조건으로 검사해 동시 수정 덮어쓰기를 방지한다.
비로그인/일반 회원/다른 센터 관리자는 저장할 수 없다. 테스트 저장은 메모리 DB 모형만 사용했다.

미리보기에서는 '공유할 공지 문구'에 제목+사진 위 문구, 이미지 준비 영역 아래의 '사진 아래에 쓰기'에 하단 문구를 불러온다.
각 문구는 이번 공지에만 수정할 수 있으며 기본 설정을 자동으로 바꾸지 않는다. 새 미리보기에서는 저장된 기본 문구를 다시 불러온다.
복사/웹 URL/앱 URL/기기 파일 공유에는 위/아래 문구를 한 번씩 결합해 전달한다.
공식 BAND 공유 인터페이스는 이미지 사이에 본문을 배치하는 기능을 제공하지 않으므로, BAND 최종 편집 화면에서 사진과 문구 위치를 확인·조정해야 한다고 안내한다.

추가 브라우저 QA (실제 컴포넌트, 메모리 설정 저장):
- 설정이 없을 때 기본 안내가 대회명/주차/항목만 포함됨.
- 위/아래 기본 문구 저장 후 다음 미리보기에서 불러옴.
- 이번 공지만 수정한 문구의 URL 인코딩과 공유 목적지 캡처 확인.
- 다시 열면 기본 설정이 복원됨.
- 기본 위/아래 문구를 결합해 복사한 실제 클립보드 내용이 기대 문구와 일치함.
- 간단한 안내와 별도로 기존 공식 결과표 PNG 4종을 유지함.
- 팀 순위표 PNG가 변경 전과 동일한 310969 bytes / 2000x2310으로 생성됨.
- CHAMP는 공유 안내가 '대회명 / 1회차 · 참가자 명단'으로 간단해져도 PNG에는 전체 참가자 4명 기록이 유지됨을 확인.

13. QA 화면 hydration 경고 수정
로컬 QA 생성기의 app/layout.jsx에서 body 인라인 스타일을 제거하고 app/qa.css의 고정 클래스로 옮겼다.
브라우저에서 body style이 색상/배경 CSS 표현으로 정규화되어 React의 최초 속성 비교와 달라지는 경로를 제거했다.
suppressHydrationWarning으로 숨기지 않았다. 운영 앱의 layout이나 기능 소스는 이번 경고 수정에서 변경하지 않았다.
새 로컬 탭에서 최초 접속, 새로고침, 1주차 미리보기 열기를 확인했다. 해당 탭의 콘솔 error/warn 조회 결과는 모두 0건이었다.
QA 생성기 node --check와 git diff --check 통과. 기존 앱 소스가 같으므로 위 production build 결과를 재사용한다.
