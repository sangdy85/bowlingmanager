BAND PC 사진 전달 — 사이트/확장프로그램 연결 보완 (2026-10-26)

문제
0.1.0 확장프로그램은 도구 모음에서 직접 실행해야 했고, 운영 사이트는 사진 저장/직접 첨부 화면을 계속 표시했다.
사이트와 설치 확장프로그램을 연결하지 않은 상태여서 설치만으로 기존 공유 버튼의 동작이 달라지지 않았다.

수정
BandOfficialShareControl: PC 사진 전달 상태와 주 버튼 추가. 사진 준비+공유 범위 확인 후 사용할 수 있다.
저장 확인 체크는 수동 첨부를 선택한 경우에만 사용하며 확장프로그램 전달을 막지 않는다.
저장/수동 첨부는 접힌 대안으로 유지. 모바일 파일 공유/문구 전용 공유/팝업 차단 시 새 탭 대안 보존.
LeagueWeeklyBandButton: 다운로드만 요구하던 설명을 PC 사진 전달과 기존 다운로드 안내로 수정.
BandPublishStatus.module.css: 기존 디자인에 맞춘 연결 상태 안내와 수동 첨부 영역.

확장프로그램 0.2.0
bridge.js는 공식 HTTPS 두 도메인의 최상위 페이지에서만 동작한다.
실제 사용자 클릭(isTrusted)으로 사이트의 PC 사진 전달 버튼을 눌렀을 때만 현재 공유 미리보기를 읽는다.
선수 기록 공유 동의, 수정한 문구, 준비된 PNG는 기존 readPreparedSource 함수를 그대로 사용한다.
공유 읽기 모듈 transfer.js만 두 공식 도메인에 공개하며 준비 사진/문구/쿠키는 웹 공개 리소스에 포함하지 않는다.
worker는 같은 확장 ID, 최상위 프레임, 실제 sender URL과 패킷 출처의 완전 일치를 검사한다.
사이트 연결 스크립트에서는 가져오기만 가능하고 BAND 첨부/다른 탭 조회/임시 자료 조회/삭제를 요청할 수 없다.
공식 출처/파일 형식/개수/크기를 다시 검증한 뒤 임시 저장하고 일반 BAND 웹사이트를 연다.
BAND에는 상시 스크립트/호스트 권한을 추가하지 않는다. 대상 밴드 새 글쓰기에서 도구 모음의 확장프로그램으로 확인 후 첨부한다.
기존 0.1.0 도구 모음 가져오기 흐름도 보존한다. 게시 버튼을 자동으로 누르지 않고 성공 이력을 쓰지 않는다.
기존 설치 폴더를 백업 후 0.2.0으로 갱신하며 사용자가 Chrome 확장프로그램과 사이트를 새로고침해야 한다.
Chrome에서 공식 사이트 접근 확인이 나타나면 사용자가 직접 확인한다.

로컬 검증
관련 BAND/상주리그 테스트 128/128 통과 (신규 확장프로그램 테스트 9개 포함).
lint: 오류 0, 기존 경고 17. typecheck 통과. npm.cmd run build 통과.
실제 Chromium 모형: 공유 동의 전 가져오기 차단, 사이트 버튼으로 사진 4개 임시 저장/대상 화면 열기.
실제 Chromium 모형: 수정 문구와 PNG 4개 전달, 파일 변경 이벤트 1회, 게시 0회.
실제 공유 React 컴포넌트: 연결됨 표시, 공유 동의 전 버튼 비활성화, 동의 후 저장 확인 없이 활성화.
사이트 버튼 응답을 수신해 전달 요청 안내가 표시되고 대기 상태가 해제됨을 확인했다.
기존 결과표 4종 생성/다운로드 버튼 보존 및 수동 첨부 대안 접힘 확인.
실제 설치된 확장프로그램에서 BAND 업로드 완료까지의 검증은 사용자 새로고침 후 남아 있다.

운영 반영 범위
공유 화면 관련 src 파일 3개만 패치하며 API/인증/DB/Prisma/모바일 앱/OAuth 자동 게시 로직은 변경하지 않는다.
운영 현재 소스를 확인한 뒤 별도 후보에서 빌드/테스트/HTTP 확인 후 교체한다.
GitHub는 기존 codex/band-official-share-20261026 브랜치에 반영하며 main 강제 덮어쓰기/병합을 하지 않는다.
