BAND 사진 첨부 순서 수정 — 확장프로그램 0.2.1 (2026-10-26)

증상: 문구를 넣고 사진을 첨부하면 사진이 문구 앞에 배치됐다.
기존 코드는 문구 입력 후 사진의 삽입 위치를 지정하지 않았고 편집기의 저장된 커서 위치와 파일 선택 시점의 상태를 동기화하지 않았다.

수정: bandComposerAction을 비동기로 만들어 문구 뒤 삽입 위치를 준비한 뒤 파일을 전달한다.
빈 글쓰기에서만 placeholder를 포함한 빈 영역을 선택하고 준비한 문구를 일반 텍스트로 입력한다.
이미 쓴 문구는 덮어쓰지 않는다. 글의 끝으로 이동하고 새 문단을 만들어 사진이 들어갈 위치를 설정한다.
공개 DOM Selection/Range와 일반 편집 이벤트로 위치를 알리고 편집기가 처리할 시간을 준다.
대기 중 작성창/밴드/커서/유효기간이 바뀌면 파일 전달 전에 중단한다.
문구 삽입 실패 시 사진만 먼저 보내지 않고 중단한다. 게시 버튼은 누르지 않는다.
BAND 내부 객체/API/인증 정보에 접근하지 않고 기존 파일 입력 change 이벤트를 사용한다.

검증: 확장 테스트 13/13, 전체 BAND/상주리그 132/132 통과. 수정 JavaScript 구문 검사 통과.
실제 Chromium 로컬 모형을 파일 목록을 따로 보여주던 방식에서, 편집기의 저장된 커서 위치에 사진을 삽입하는 방식으로 보완했다.
빈 작성창(placeholder 포함), 기존 글+맨 앞 저장 커서에서 모두 문구→사진 4장, 파일 변경 1회, 게시 0회 확인.
문구 삽입 실패 및 준비 중 밴드 변경은 사진 전달 전에 차단함을 테스트했다.
기존 문구 보존 및 console error/warn 0개 확인.
실제 BAND 글쓰기 DOM 구조는 읽기 전용 확인 후 새로 연 빈 작성창을 취소했다. 실제 BAND 게시/업로드는 이 검증에서 실행하지 않았다.
사용자가 새로고침한 0.2.1 확장프로그램에서 실제 BAND의 최종 배치 확인은 남아 있다.
