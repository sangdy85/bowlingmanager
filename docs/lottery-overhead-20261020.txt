확인한 문제
- 매 프레임마다 모든 공의 구면·핑거홀·조명·마블 무늬를 CPU로 다시 만들고 큰 정점 배열을 GPU에 전송했다.
- 출발 카메라는 낮은 근접 시점이었고, 선두만 따라가며 순위 변경과 피격 때 시점이 크게 이동할 수 있었다.
- 이동은 100ms 간격의 선형 보간이어서 피격·후진 구간에서 속도 변화가 각지게 보일 수 있었다.
- 그리지 않는 프레임에서도 순위 정렬을 했고, resize에서는 크기가 같아도 캔버스를 초기화했다.

변경 내용
- 출발부터 높은 광각 시점 사용. 선두와 앞쪽 경기 그룹을 함께 화면에 담는다.
- 공 한 명을 선택하면 해당 공을 부드럽게 추적한다. 전체 맵은 별도로 유지한다.
- 대기·완료 상태에서도 전체 맵 버튼이 즉시 작동한다. 모바일에서 전체 코스 표시 확인.
- 8종 공 모양과 재질을 한 번 생성해 캐시하고 GPU에서 회전·조명·위치만 갱신한다.
- 동적 효과 버퍼는 크기가 커질 때만 확보하고 매 프레임 재사용한다.
- resize에서도 실제 픽셀 크기가 달라질 때만 캔버스를 갱신하며, 순위 HUD 갱신을 그림 재생과 분리한다.
- 피격·후진 위치를 표본 범위를 벗어나지 않는 연속 곡선으로 보간한다. 실제 표본과 결승선 도착 시각은 유지한다.
- 50초, 아이템 12종/100개, 슬로모션, 당첨 이후 전원 완주, 기존 저장 방식은 유지한다.

성능 비교
같은 가상 경기의 피격 장면 50개, 실제 렌더러와 모의 WebGL로 CPU 처리·버퍼 전송량 비교.
GPU 실행 시간을 제외한 수치이며 실제 브라우저 FPS를 측정한 결과는 아니다.
- 47명: CPU 중앙값 53.09→5.23ms, 95백분위 76.37→8.81ms. 동적 정점 업로드 1,727,657→94,308 byte/frame.
- 197명: CPU 중앙값 112.89→8.37ms, 95백분위 184.64→11.62ms. 동적 정점 업로드 7,428,154→215,361 byte/frame.
- 그림은 더 많은 공을 함께 표시하며 모델을 CPU에서 재생성하지 않는다. 장치별 실제 FPS는 별도 측정하지 않았다.
