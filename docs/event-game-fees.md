# 참석 조사 기반 게임비 확인

작업 브랜치: `codex/event-game-fees` (기준 커밋 `1299cca`). 기존 카드 결제 및 오픈뱅킹 작업은 각각의 작업 트리에 보존되어 있으며 이 변경에 포함되지 않는다.

## 사용자 흐름

1. 동호회 관리 마지막 메뉴 **회비 및 게임비 계좌 설정**에서 관리자가 회비계좌와 게임비 계좌를 각각 저장한다. 은행명·계좌번호·예금주를 받는다. 은행 인증이나 API 키는 필요하지 않다.
2. 일정 상세의 참석 조사에서 **참석**을 선택한다. 게임비 입금·현장 결제 버튼이 참석 선택 버튼 왼쪽에 나타나며, 좁은 화면에서는 줄바꿈한다.
3. **게임비 입금**은 계좌 안내와 복사 기능을 보여준다. 은행 앱에서 송금한 사용자가 **입금 완료**를 누르면 확인 요청이 저장된다.
4. **현장 결제**도 별도 안내창에서 **현장 결제 완료**를 눌러야 확인 요청이 저장된다.
5. 관리자는 같은 참석자 명단에서 내역을 대조한 후 확인한다. 관리자와 사용자는 같은 서버 상태를 읽는다. 화면이 활성화된 동안 30초마다 갱신하며, 앱 복귀 또는 당겨서 새로고침도 지원한다.

| 단계 | 관리자 표시 | 사용자 표시 |
| --- | --- | --- |
| 참석 / 수단 선택만 한 상태 | 미결제 | 게임비 입금·현장 결제 버튼 |
| 입금 완료 신고 | 입금 확인 요청 / 입금 확인 버튼 | 입금 확인 요청 |
| 입금 확인 승인 | 입금 최종 확인 | 입금 최종 확인 완료 |
| 현장 결제 완료 신고 | 현장 결제 확인 요청 / 현장 결제 확인 버튼 | 현장 결제 확인 요청 |
| 현장 결제 확인 승인 | 현장 결제 최종 확인 | 현장 결제 최종 확인 완료 |

회비 확인 로직은 이번 변경에서 추가하지 않는다. 실제 송금/결제 실행, 은행 자동조회, 자동입금확인, 알림 발송은 하지 않는다. 게스트는 로그인 사용자와 연결되어 있지 않아 이번 본인 신고 흐름의 대상에서 제외된다.

## 저장 및 권한

- `TeamPaymentAccount`: 동호회·종류별 하나의 계좌. 관리자만 조회·수정 가능하며 일반 회원에게는 일정 응답의 게임비 계좌만 제공한다. 회비 계좌와 혼동하지 않는다.
- `TeamEventAttendance`: 게임비 상태·버전·신고/확인 시각·확인 관리자·신고 당시 계좌를 보관한다. 참석 상태를 바꿔도 결제 정보는 지워지지 않는다.
- `TeamGameFeeAudit`: 상태 전환과 행위자, 대상, 계좌 스냅샷을 같은 트랜잭션에 기록한다. 일정 삭제 후에도 감사 이력이 남는다.
- 활성 동호회의 현재 회원만 접근한다. 일반 회원은 자기 신고만 할 수 있고 다른 회원의 결제 상태를 받지 않는다. 팀장/매니저만 승인 가능하다.
- 신고 대기 중에는 본인이 **확인 요청 취소** 후 결제 수단을 다시 선택할 수 있다. 취소는 환불이 아니다. 최종 확인 후에는 사용자 재신고·취소 및 중복 확인을 막는다.
- 상태 버전으로 오래된 승인과 중복 제출을 차단한다. 계좌 설정에도 버전을 사용한다. 계좌가 변경된 오래된 안내창에서는 신고를 차단하고 재확인/관리자 문의를 안내한다.
- 참석 마감/추첨 완료 뒤에도 결제 신고·확인이 가능하다. 불참으로 변경한 기존 신고도 관리자가 명단의 불참 필터에서 확인할 수 있다.

## API

- `GET /api/mobile/v1/teams/:teamId/payment-accounts`: 관리자 계좌 설정 조회
- `PUT /api/mobile/v1/teams/:teamId/payment-accounts`: `kind`, `bankName`, `accountNumber`, `holderName`, `revision` 저장
- `POST /api/mobile/v1/teams/:teamId/events/:eventId/game-fee`: `action`, `revision` 전달
  - 사용자: `REQUEST_TRANSFER`(+ `accountId`, `accountRevision`), `REQUEST_CASH`, `CANCEL_REQUEST`
  - 관리자: `CONFIRM_TRANSFER`, `CONFIRM_CASH` (+ `memberId`)
- 기존 일정 조회에 `gameFeeAccount`, `myGameFee`, 권한별 `attendance[].gameFee` 추가
- 모바일 Bearer 인증을 사용한다. 웹 쿠키 인증으로 쓰기 요청을 보낼 때는 같은 Origin을 요구한다.

## 기존 정산 및 적용

새 앱의 정산 화면은 게임비를 일정 상세로 안내하고 신규 게임비 청구서 선택지를 제거한다. 기존 회비/기타 정산 및 과거 게임비 청구서는 보존한다. 과거 `TeamChargeTarget.PAID`에는 결제 수단이 없으므로 입금/현장 결제로 임의 변환하지 않는다. 기존 정산 API는 이전 앱과 과거 기록의 호환성을 위해 유지한다. 새 참석자 결제 상태는 기존 청구서 금액 합계에 자동 반영되지 않는다.

실제 적용 전에 기존 일정에 게임비 수납 기록이 있는지 확인해야 한다. 과거 수납 명단을 새 미결제 상태로 재안내하지 않도록, 기존 기록과 진행 중 일정의 전환 시점을 운영자가 정한다. 자동 과거 데이터 변환은 수행하지 않았다.

새 마이그레이션 `20261010050000_add_attendance_game_fees`는 기존 테이블/제약을 재생성하지 않는 추가 방식이다. 운영 DB 마이그레이션 및 서버/앱 배포는 수행하지 않았다. 적용 시 DB 마이그레이션 → 서버 → 앱 순서가 필요하다.

## 검증

- Node 20에서 관련 서버 테스트 **77개 통과**: 신규 실제 SQLite 마이그레이션/상태 전환/권한/원자적 감사 저장/이력 보존과 기존 일정·정산·운영 도구 회귀 테스트.
- 실제 Next.js HTTP 통합 테스트 **4개 통과**: Bearer 인증, 계좌 설정 권한, 본인 신고, 관리자 승인, 상호 상태 조회, 다른 동호회 접근 및 오래된 승인 차단. 별도 임시 앱/DB를 사용하며 운영 주소로 접속하지 않는다.
- `npm run build`: lint, TypeScript, Prisma client 생성, Next.js 프로덕션 빌드. 기존 lint 경고 18개, 오류 없음.
- Flutter 위젯 테스트 `mobile/test/club_game_fee_widgets_test.dart` 추가: 두 단계 완료 신고, 계좌 미설정, 관리자 확인, 최종 표시 및 중복 신고 방지.
- 이 실행 환경에는 Flutter/Dart SDK가 없어 앱 분석·테스트·기기 실행은 미실행. SDK가 있는 환경에서 다음 검증이 필요하다.

```sh
cd mobile
flutter analyze
flutter test test/club_game_fee_widgets_test.dart test/club_event_models_test.dart test/club_events_api_test.dart test/club_event_attendance_management_test.dart test/club_finance_form_target_test.dart test/club_payment_accounts_screen_test.dart
```

## 다음 단계 검증 보완 (2026-10-10)

- 계좌 설정 중 다른 관리자가 먼저 저장한 경우, 편집창의 **최신 계좌 불러오기**로 현재 값을 읽고 최신 버전으로 다시 저장할 수 있다. 최신 값 확인 전에는 재저장을 비활성화한다.
- 결제/확인 안내창에 스크롤을 적용해 작은 화면과 큰 글씨에서 완료 버튼에 접근할 수 있게 보완했다.
- 회비/게임비 계좌 분리 저장, 계좌 충돌 복구 위젯 테스트 및 API 경로·버전 전달 테스트를 추가했다. Flutter 실행 검증 여부는 아래 한계와 동일하다.
- Flutter SDK가 없고 공식 다운로드 요청이 HTTP 404로 실패해 이 환경에서 추가 설치·앱 실행을 완료하지 못했다. 프로젝트의 SDK/의존성 조건을 낮추지는 않았다.

저장소에 변경 파일을 적용한 뒤 다음 명령으로 PC에서 검증한다. 스크립트는 첫 실패에서 중단하고 성공으로 처리하지 않는다. Windows의 npm.ps1 실행 정책 문제를 피하도록 Node에서 배치 실행기를 호출한다.

```powershell
node scripts/verify-game-fees.cjs
```

기본 동작은 Node 20 및 Flutter/Dart 사전 확인 → Prisma 클라이언트 생성 → 임시 DB 서버 테스트 → 실제 HTTP 테스트 → 서버 빌드 → Flutter 의존성 복원 → analyze → 관련 앱 테스트 순서다. `flutter pub get`으로 잠금 파일이 변경되면 자동 진행하지 않고 차이를 검토하도록 중단한다.

```powershell

node scripts/verify-game-fees.cjs --server-only
# 사용자 PC에서 Flutter 검증만 실행 (서버 검증은 별도)
node scripts/verify-game-fees.cjs --mobile-only
```

스크립트는 운영 DB 마이그레이션, 서버 연결/배포, APK 배포, Git 커밋/푸시/머지를 실행하지 않는다. 기존 `release-bowling.ps1`은 배포 동작이 있으므로 이번 검증에 사용하지 않는다.
