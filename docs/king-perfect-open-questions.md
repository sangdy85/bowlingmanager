# 미확정 사항과 운영 적용 전 확인

| 확인 항목 | 구현한 처리 | 실제 확인 필요 |
|---|---|---|
| 퍼펙트센터 ID | KING_PERFECT_CENTER_IDS, 이름 비교 없음 | 운영 DB의 정확한 센터 ID를 담당자가 확인하여 환경변수 설정 |
| 예선 횟수/반영 기록 | 제한 없음/횟수, 최고/최근, 명시 확인 | 원본 규칙 확정; 첫 기록 이후 이 정책은 잠김 |
| 동점 | 기본 자동 확정 차단, ID 순서+사유 | 재경기/추첨 등 현장 판정 방법은 주최측 결정 |
| 단계별 게임 수/판정 | 1게임은 임시, 확인 체크, 합계/최고 게임 | 정확한 게임 수와 시리즈 판정 |
| 2R 이동 | 12매치 번호의 사용자 매핑, 확인 체크 | 원본 이미지의 승리 이동 번호 대조 (이미지 파일 자체는 제공되지 않음) |
| 핸디 상한 | 리그와 동일 300 또는 상한 없음 선택 | 예선 단순 합산과 본선 리그 규칙 차이 확인 |
| 상금 기준액 | 납부액/발생액/지정액, 별도 확정 | 예선 수입 범위, 잔여 10%, 실제 지급 확인 |
| 취소/결원 | 자격 취소, 예선 잠금 해제 및 재선정, 원장 수동 정리 | 차순위 대체/기권승 규칙; 자동 부전승은 구현하지 않음 |
| 사이드 중복 시상 | 명단·점수 순위 제공, 기본 결과와 분리 | 상금/행운권 중복 조건과 시상; 자동 시상 없음 |

## 남은 기능 / 한계
- 게임당 선수 자리 드래그 대신 24명 확정 후 1R 생성 전 두 시드 선택 교체를 제공한다.
- 원본 엑셀 이미지가 첨부되지 않아 텍스트에 명시된 1R 시드만 정확히 재현했다.
- PDF는 브라우저 인쇄 저장. 직접 PDF 생성 및 PNG 이미지 내보내기는 미구현.
- 엑셀 입력은 해당 본선 경기 단위 entryId/number/raw 표준 열만 지원. 예선 일괄 가져오기, 이름 기반 자동 매칭은 미구현.
- 모바일 반응형 웹이며 Flutter 앱 전용 네이티브 탭/API는 미구현. 기존 모바일 API는 변경하지 않는다.
- 공개 화면은 최종 순위/원점수/행운권 중심. 참가자 셀프 접수, 공개 실시간 대진, 공개 상금 상세는 미구현.
- 임의 일정 변경은 미구현. 월별 셋째 일요일 고정, 예선 접수 기간은 설정 가능.
- 대회 기본명 수정 UI는 미구현. 생성 시 대회명을 설정한다.
- 사유 입력/감사 기록은 구현했지만 감사 전후 스냅샷을 비교하는 전용 UI는 없고 최근 50개 작업 요약만 표시한다.
- 전체 회차 aggregate를 직렬화하므로 대규모 상시 접수 부하 테스트와 감사 로그 용량 측정이 필요하다.
- 운영 DB에 직접 쓰는 우회 스크립트의 회차 무결성까지 보호하는 복합 외래키는 추가 검토가 필요하다.

## 운영 적용 절차 (이번 작업에서는 수행하지 않음)
1. 변경 코드 및 migration 검토, 실제 DB 백업, 스테이징에서 동일 migration 검증.
2. 검증된 실제 센터 ID를 KING_PERFECT_CENTER_IDS에 지정. 빈 값은 비활성화.
3. migration 적용 및 Prisma Client 생성 후 앱 배포. 운영 적용은 별도 승인된 작업에서만 실행.
4. 센터 owner/managers로 생성·조회·수정, 타 센터 관리자 차단 확인.
5. 규칙 미확정 항목을 주최측과 확인하고 관리자 설정에 명시. 실제 회원 자격과 핸디 대조.
6. 비공개 연습 회차에서 실제 장비 크기/프린터/엑셀 양식 확인.
7. 참가비 수동 입금 확인 담당자와 정산 재확정 절차 지정.
8. 과거 회차 데이터/감사 스냅샷 보존과 백업 정책 확인 후 실제 대회 운영.
