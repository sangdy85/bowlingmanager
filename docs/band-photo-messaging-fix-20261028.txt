BAND 최종 결과표 사진 전달 오류 보완 — 2026-10-28

기준: codex/band-official-share-20261026, d4d557e (작업 전 clean).

진단:
- 사용자 캡처에는 최종 결과 PNG가 이미 생성되어 있음.
- 오류는 PC BAND 사진 전달 시 확장프로그램 응답 검사 단계.
- 초기 문서 주소와 현재 Next.js 경로가 다르면 기존 worker가 요청에
  응답하지 않는 상황을 재현. 브리지의 기존 연결 확인 오류와 일치.
- 설치 폴더 11개 파일은 기존 0.2.3 패키지 해시와 일치함.

변경 (확장프로그램 0.2.4):
- 같은 확장프로그램의 최상위 공식 사이트 스크립트인지 확인하고,
  현재 페이지 URL과 메시지 출처의 공식 origin 일치를 검사.
  같은 origin 내 경로·쿼리·해시 이동을 잘못 거절하지 않음.
- 다른 origin, 프레임, 확장프로그램 및 불필요한 명령은 계속 차단.
- 주소 검증 거절 시 명확한 오류 응답. 무응답 및 업데이트로 무효화된
  스크립트는 확장프로그램/페이지 새로고침 방법을 안내.
- manifest 권한·BAND 사진 첨부 방식·수동 최종 게시 동작 유지.

검증:
- BAND·레인·기존 기록 보호 회귀 테스트 173개 통과.
- JS 구문 검사 및 git diff --check 통과.
- 실제 986,121바이트 최종 결과표 PNG로 Chromium 로컬 모형 검증:
  trusted click → 실제 worker listener → 임시 IndexedDB → 첨부 모형,
  사진 1장/파일 변경 1회/첨부 1회/게시 0회,
  위 문구 → 결과표 → 아래 문구, 커서 끝 유지 확인.
- 2MB 이상 메시지 보존, 두 공식 도메인의 경로 이동, 외부 출처 차단,
  무응답·무효화된 확장프로그램 안내 회귀 검사.
- 실제 설치 브라우저와 BAND를 연결하는 확인은 사용자가 확장프로그램과
  페이지를 새로고침한 뒤 진행해야 함. 실제 BAND에 테스트 게시하지 않음.
- 이번 변경은 서버 src/DB/API 변경이 없어 서버 재배포·Next 빌드 불필요.

적용:
- 현재 설치 폴더의 원본을 별도 백업한 뒤 0.2.4 파일로 교체.
- chrome://extensions/ → BowlingManager BAND 사진 전달 → 새로고침,
  이어서 볼링매니저 페이지 새로고침 후 최종 결과표를 새로 준비.
- 운영 서버/운영 DB/기존 BAND 게시글 변경 없음.
